### Step 2 — Purge the value from the git history

Do this on a **FRESH CLONE** (never on a working repository you still depend on), and only after step 1:

```
git clone <remote-url> <fresh-clone-dir>
cd <fresh-clone-dir>
git filter-repo --replace-text <replacements-file> --force
git push --force --all
git push --force --tags
```

- it must **never** leave this machine (do not commit it, do not upload it, do not paste it in chat);

```
literal:<THE-EXACT-VALUE>==>REMOVED
literal:<THE-EXACT-VALUE-2>==>REMOVED
```

fingerprints in section 1 are what you use to confirm afterwards that the right value was purged.

### Step 4 — Check the provider's audit logs for use since the commit date

For every credential revoked in step 1, pull the provider's audit/access log back to the date the

- calls from IPs or regions that do not look like yours;
- request volumes that do not match your usage;
- usage that continues *after* the revocation timestamp (a sign the key was cached or copied).

If there is unexplained use, treat it as a compromise: rotate again, and hunt for the second copy of
the value.
